# Pool Monitor Card: Recipes

Home Assistant `template` sensors that plug into this card. The card reads
entities; these build the entities it cannot build itself. Paste a block into
your Home Assistant configuration, reload templates, and point the card at the
entity it creates.

Every entity id written `sensor.YOUR_SOMETHING` is a placeholder for one of
yours. Nothing on this page is a card option, and nothing here needs a new
release of the card to work.

## Answers to a specific request

These carry a formula, which no registry holds and no generator can derive.
Each one names the request it answers, and says what was actually run.

### A free chlorine target that follows the water temperature

Asked for by @hfuerst in [pool-monitor-card#84](https://github.com/wilsto/pool-monitor-card/issues/84).

The five rows below are @hfuerst's own table, not ours: this recipe carries
his numbers, and the only thing derived from the card is that `setpoint_entity`
accepts them. Swap in whatever table you keep.

```yaml
template:
  - sensor:
      - name: "Free chlorine setpoint"
        unique_id: free_chlorine_setpoint
        unit_of_measurement: "mg/l"
        state: >
          {% set t = states('sensor.pool_water_temperature') | float(24) %}
          {{ 0.4 if t < 20 else 0.55 if t < 25 else 0.7 if t < 28 else 1.0 if t < 30 else 1.25 }}
```

And the card reads it:

```yaml
type: custom:pool-monitor-card
sensors:
  free_chlorine:
    entity: sensor.pool_free_chlorine
    setpoint_entity: sensor.free_chlorine_setpoint
    unit: "mg/l"
    step: 0.1
```

Three things are worth knowing before you paste it.

**The green zone is `setpoint ± step`.** `step: 0.1` around a target of 0.4
gives green from 0.3 to 0.5. Rows of different widths are a compromise:
`step` is a fixed number and cannot be read from an entity, so the band
centre follows the temperature and the band width does not. `step_low` and
`step_high` make the band asymmetric if that helps.

**Set `unit` and `step` yourself.** The built-in `free_chlorine` preset ships
the US scale, in ppm. A European mg/l table is roughly five times lower, and
`setpoint_entity` replaces the target but neither the unit nor the step.

**Leave `min` and `max` out.** The bar then spans `setpoint ± 3 × step`, which
keeps the target at the centre and the colours where the bands actually are.
Pinning `min` and `max` slides the numbers off centre while the colour ramp
stays put, so the bar ends up disagreeing with the badge.

**Verified.** Run end to end on a Home Assistant test instance on 2026-08-23. The water temperature was swept from 18 °C to 31 °C with no restart: the target followed on its own through 0.4, 0.55, 0.7, 1.0 and 1.25 mg/l, and a reading held at 0.7 mg/l walked from "Too High" through "Ideal" to "Too Low" as the water warmed. The card half is also covered by the card's own test suite.

**Not verified.** What the card falls back to when the target sensor itself goes unavailable was not exercised on the instance. It is covered by the unit tests, which is a weaker proof than a run.
